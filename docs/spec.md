# iso-scene language — спецификация v1 (черновик)

Статус: **draft**. Нормативная грамматика — [`grammar.ebnf`](grammar.ebnf).
Ключевые слова и идентификаторы — латиница; текст сообщений может быть любым.

## 1. Назначение

iso-scene описывает **3D-модели** и **сцены** из простых тел и компилирует их
в пиксель-арт разных проекций. Модель не зависит от разрешения и проекции:
изометрия, вид сверху, вид сбоку и воксели — это бэкенды одного и того же
описания.

Язык декларативный, но допускает циклы и условия для генерации повторяющихся
деталей. Вычисление всегда ограничено бюджетом шагов (fuel), поэтому плохой
вход не может повесить редактор.

## 2. Файлы

| Расширение | Роль | Что разрешено на верхнем уровне |
|---|---|---|
| `.model` | переиспользуемый объект | `version`, `material`, `object` |
| `.scene` | композиция | `version`, `include`, `material`, `object`, `render`, `scale`, `canvas`, `sun`, `ambient`, `background`, `let`, `var`, `for`, `if`, `place` |
| `.walls` | раскладка стен | `version`, `height`, `thickness`, `material`, `layout` |

Один и тот же синтаксис для `.model`/`.scene`; роль определяется расширением.
`.walls` — отдельный формат, см. [`walls.md`](walls.md). Сцена может
включать модели через `include`. Модель не может включать сцену.

`include "path"` — путь относительно текущего файла. Абсолютные пути и выход
за корень проекта запрещены. Циклы include запрещены; глубина — не более 16.

## 3. Лексика

- Кодировка UTF-8; BOM в начале допускается и игнорируется.
- Пробелы, табы, `\r`, `\n` разделяют токены и не значимы для грамматики.
- Комментарии:
  - `//` до конца строки;
  - `/* ... */`, **не вложенные**. Незакрытый комментарий — ошибка.
- Идентификатор: `[A-Za-z_][A-Za-z0-9_]*`.
- Число: `[0-9]+(\.[0-9]+)?`. Без знака, экспоненты, `NaN` и `inf`.
  Отрицательные числа — унарный минус. `1.` и `.5` запрещены.
- Строка: `"..."`, экранирование `\\`, `\"`, `\n`, `\t`. Другие escape —
  ошибка.
- Цвет: `#RRGGBB` (шесть hex-цифр).
- Пунктуация: `{ } ( ) ; , = + - * / % == != < <= > >= && || ! ..`
- Ключевые слова: `version include material object render scale canvas sun
  ambient background place mirror anchor for in if else let var true false
  box cyl sphere slantbox slantcyl ramp at size radius height offset rise
  rot`.

Лексер обязан корректно различать `1..5` (число, `..`, число) и `1.5`
(одно число).

## 4. Значения и типы

| Тип | Смысл |
|---|---|
| `number` | конечное f64; геометрические координаты и размеры — в блоках |
| `bool` | `true` / `false` |

- Все геометрические числа — **блоки**. Язык не знает сантиметров, метров и
  пикселей. Физический смысл блока задаёт проект.
- `scale` — целое число пикселей на блок; это параметр рендера, не модели.
- Счётчик цикла — целое число (проверяется при вычислении границ); он
  неизменяем.
- Строки и цвета — не значения выражений, а литералы конкретных директив
  (`include`, `material`, `background`). Переменных строк и цветов в v1 нет.
- `let` создаёт неизменяемую переменную, `var` — изменяемую.
- Присваивание возможно только `var`. Попытка присвоить `let`, счётчику цикла
  или `w`/`d` объекта — ошибка.

### 4.1 Области видимости

- Переменные видимы от объявления до конца текущего блока `{ ... }`.
- Вложенный блок может объявить своё имя, но **затенять** видимое имя нельзя
  (`E0303`). Это упрощает чтение и проверку.
- Счётчик `for` виден только в теле цикла.
- Тело объекта имеет собственную область; `w` и `d` — неизменяемые имена в ней.
- Верхний уровень сцены — отдельная область.
- Директивы `scale`, `canvas`, `sun`, `ambient`, `background` и заголовок
  объекта принимают только **константные** выражения: литералы, `+ - * / %`,
  скобки и унарный минус. Переменные там запрещены (`E0310`).


## 5. Структура программы

Первая значимая инструкция файла — `version 1;`. Другая версия — ошибка
`E0203`.

### 5.1 Сцена

```c
version 1;

include "chair.model";

render iso;
scale 32;
canvas (30, 24, 8);
sun (135, 45);
ambient 0.35;
background #1a1c22;

for row in 0..4 {
    for col in 0..5 {
        place chair at (col * 5, row * 4, 0) rot 0;
    }
}
```

- `render iso | top | front | side;` — обязательная директива, ровно одна.
- `scale` — целое `1..256`, обязательно.
- `canvas (w, d, h);` — необязательный минимальный габарит в блоках.
  Итоговый размер — максимум из габарита содержимого и `canvas`.
- `sun (azimuth, altitude);` — градусы; азимут `0..360`, высота `0..90`.
  По умолчанию `(135, 45)`.
- `ambient` — `0..1`; по умолчанию `0.35`.
- `background` — цвет или `transparent`; по умолчанию `transparent`.
- `place name at (x, y, z) rot r [anchor a];` — размещение объекта. `r`
  приводится к `0/90/180/270`; иное значение — ошибка `E0306`. `a` выбирает,
  какая точка следа объекта попадает в `(x, y, z)`: `back` (мин. x и y, по
  умолчанию), `center`, `front` (макс. x и y — ближний к зрителю угол),
  `left` (мин. x, макс. y), `right` (макс. x, мин. y) или `cell` — клетка, на
  которой стоит спрайт: ближний угол сдвигается на клетку внутрь, поэтому
  `place at (x, y) anchor cell` ставит спрайт на клетку `(x, y)` при любом
  размере следа. Точка берётся от уже повёрнутого следа, поэтому якорь
  одинаково работает при любом повороте.

### 5.2 Модель

```c
version 1;

object chair (1.8, 1.8) {
    let leg = 0.16;
    let leg_h = 1.64;

    box at (0.08, 0.08, 0) size (leg, leg, leg_h) material metal;
    box at (1.56, 0.08, 0) size (leg, leg, leg_h) material metal;
    mirror y;

    box at (0, 0, leg_h) size (w, d, 0.16) material wood;
}
```

`object name (w, d) { ... }`:

- `w`, `d` — положительные конечные константы, план объекта в блоках.
- Внутри тела доступны неизменяемые `w` и `d`.
- Имена объектов глобальны после include; дубликат — ошибка `E0303`.
- `place`, `render`, `scale`, `include` внутри объекта запрещены.
- Объект вычисляется один раз при объявлении; `place` только трансформирует
  готовый набор тел. Параметры объекта (переопределение `w`/`d` при
  размещении) появятся в v1.1; синтаксис `object name (w, d)` к этому готов.

## 6. Фигуры

Все фигуры осевые, кроме `slantbox`, `slantcyl`, `ramp`.

| Команда | `at` | Параметры |
|---|---|---|
| `box` | минимальный угол `(x, y, z)` | `size (w, d, h)` — протяжённости |
| `cyl` | центр основания `(x, y, z)` | `radius r`, `height h` |
| `sphere` | центр `(x, y, z)` | `radius r` |
| `slantbox` | минимальный угол основания | `size (w, d, h)`, `offset (dx, dy)` — сдвиг верхней грани |
| `slantcyl` | центр основания | `radius r`, `height h`, `offset (dx, dy)` |
| `ramp` | минимальный угол основания | `size (w, d)`, `rise (h0, h1)` — высота в начале и конце по +X |

- `w`, `d`, `h`, `r` должны быть `> 0`; иначе `E0307`.
- Координаты и размеры конечны и по модулю не больше `1_000_000` блоков.
- `material` необязателен; по умолчанию `wood`.

### 6.1 Материалы

Встроенные имена: `wood`, `metal`, `light`, `glass`, `dark`, `red`, `white`.
Их точные цвета задаёт бэкенд; для воспроизводимости они зафиксированы в
[`backends.md`](backends.md).

Свой материал:

```c
material oak = "materials/oak.toml";
```

```toml
name = "Дуб"
color = "#BD8953"
roughness = 0.65
metallic = 0.0
specular = 0.3
outline = "#4B3528"

[texture]
type = "wood"      # none | wood | fabric
axis = "z"         # x | y | z
scale = 4.0
strength = 0.12
seed = 7
```

- Путь относительный и считается от файла, где объявлен материал (для
  включённой модели — от её каталога); выход за корень — `E0502`.
- Одинаковый алиас с тем же путём в нескольких включённых моделях допускается;
  разные пути под одним именем — `E0303`.
- Неизвестный материал — `E0305`.
- Псевдоним материала уникален в пределах файла; конфликт при include —
  `E0303`.

### 6.2 Зеркало

`mirror x;` / `mirror y;` дублирует **все фигуры, добавленные в объекте до
этой строки**, относительно плоскости `x = w/2` или `y = d/2`.

Следствие: порядок важен. Сначала ножки, потом `mirror`, потом столешница —
иначе столешница тоже удвоится. Вложенные зеркала допустимы и дают
экспоненциальный рост числа фигур; его ограничивает лимит фигур.

## 7. Выражения и инструкции

### 7.1 Выражения

Приоритет (ниже — слабее):

```
||
&&
== != < <= > >=
+ -
* / %
унарные - !
```

- `&&` и `||` вычисляются с коротким замыканием.
- `%` — остаток с знаком делимого (как в C/Rust).
- Деление на ноль — ошибка `E0308`, а не `inf`.
- Сравнения дают `bool`; `if` требует `bool`.
- Строки и цвета в арифметике не участвуют.
- Вызовов функций нет.

### 7.2 Инструкции

```c
let a = 1.5;
var b = 2;
b = b + 1;
b += 0.5;

for i in 0..10 { ... }

if (b > 2) { ... } else if (b == 2) { ... } else { ... }
```

- `for i in start..end` — полуинтервал `[start, end)`. Границы вычисляются
  один раз и должны быть целыми; иначе `E0309`. Если `start >= end`, тело не
  выполняется. Счётчик неизменяем.
- `if` / `else if` / `else` — как в C; блок обязателен.
- `break` и `continue` в v1 **отсутствуют**.
- `while` в v1 **отсутствует**: главный источник зависаний. Появится вместе
  с fuel в v1.1.
- Пользовательских функций в v1 нет. Их роль выполняют объекты; параметры
  объектов — v1.1.

## 8. Вычисление

Порядок:

1. лексер;
2. парсер → AST;
3. статическая проверка: имена, типы, константы, дубликаты, include;
4. вычисление объектов и сцен → `SceneGraph` (3D-тела + материалы);
5. бэкенд → изображение / воксели / Tiled.

Свойства:

- **Детерминизм.** Одинаковый вход и параметры дают одинаковый результат.
  Порядок обхода фиксирован; итерация по хеш-таблицам не влияет на вывод.
- **Тотальность.** Любой вход либо даёт результат, либо диагностику. Паники,
  `unwrap` на пользовательских данных и зависания запрещены.
- **Fuel.** Каждая инструкция и каждая итерация цикла списывают 1 шаг.
  Значение по умолчанию — `1_000_000`, задаётся CLI (`--fuel`), но не языком.
  Исчерпание — `E0401` со спанами. Так как fuel строго убывает, вычисление
  всегда завершается.
- **Изоляция.** Язык не выполняет произвольный код и не ходит в сеть.
  Единственный ввод-вывод — чтение include и материалов внутри корня проекта.

## 9. Лимиты

| Лимит | Значение | Ошибка |
|---|---:|---|
| размер одного файла | 1 MiB | `E0402` |
| суммарный размер include | 8 MiB | `E0402` |
| глубина include | 16 | `E0403` |
| токенов | 1 000 000 | `E0402` |
| вложенность блоков | 128 | `E0402` |
| объектов | 4 096 | `E0402` |
| фигур | 100 000 | `E0402` |
| размещений | 100 000 | `E0402` |
| шагов вычисления (fuel) | 1 000 000 | `E0401` |
| сторона canvas | 8 192 блока | `E0402` |
| выходное изображение | 8 192 px на ось | `E0402` |
| `scale` | 1..256 px/блок | `E0304` |
| координата | ±1 000 000 блоков | `E0304` |
| строка | 4 096 байт | `E0402` |

Лимиты — часть контракта: их превышение обязано быть диагностикой, а не
падением или OOM.

## 10. Диагностика

Каждая ошибка содержит:

- файл, диапазон байт, строку и столбец;
- стабильный код;
- сообщение;
- при необходимости — пояснение и подсказку.

Коды:

| Код | Категория |
|---|---|
| `E01xx` | лексика: комментарий, строка, число, символ |
| `E02xx` | синтаксис: ожидался токен, неожиданный токен, версия |
| `E03xx` | имена и типы: неизвестное имя, тип, дубликат, материал, поворот, размер |
| `E04xx` | лимиты и fuel |
| `E05xx` | include и пути |
| `E06xx` | рендер и экспорт |

Реализация обязана сообщать хотя бы первую ошибку. Восстановление после
ошибки и несколько диагностик за проход — желательно, но не требуется для
v1.

## 11. Бэкенды

`SceneGraph` — набор 3D-тел с материалами и границами. Бэкенд выбирает
проекцию и масштаб.

### iso

```
screen_x = (x - y) * scale
screen_y = (x + y) * scale / 2 - z * scale
```

Блок на экране — ромб `2*scale × scale`; при `scale = 32` это 64×32.
Вертикаль не сокращается. Порядок отрисовки — от дальних к ближним, с
z-буфером.

### top

Ортогонально сверху: `x` вправо, `y` вниз, `z` — глубина. Один блок —
`scale × scale` пикселей.

### front / side

Ортогонально сбоку: `front` — `x` вправо, `z` вверх; `side` — `y` вправо,
`z` вверх. Глубина — по третьей оси.

### voxel

Воксельный экспорт доступен через CLI:

```bash
iso-scene voxel scene.scene --density 8 -o out/model.vox
```

- шаг сетки — `1 / density` блока;
- размеры — `ceil(extent / step)`, не больше 256 по каждой оси;
- цвет — базовый `color` материала;
- формат — `MagicaVoxel` VOX;
- модель и сцена для него не меняются.

### Tiled

Экспорт доступен через CLI:

```bash
iso-scene tiled scene.scene -o out/tiled
```

- изометрическая карта `scene.tmj`;
- тайлсет пола и атлас объектов;
- слой `floor` и **object layer** `objects` с тайловыми объектами;
- только `render iso`;
- несколько объектов на одну клетку разрешены;
- объекты могут быть подняты по `z`, высота сохраняется в свойстве;
- объекты сортируются по глубине (`x + w + y + d + z`), порядок сохраняется
  в object layer;
- рядом пишется `preview.png` для сравнения с ISO-рендером.

## 12. Версионирование

- `version 1` — текущая версия.
- Ломающие изменения повышают версию и сопровождаются конвертером.
- Добавление необязательных директив и параметров — минорная версия.
- Спецификация и грамматика меняются одним коммитом.
